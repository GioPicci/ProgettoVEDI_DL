# AGENTS.md

Research project: DINOv3-based Point-of-Interest detection/classification on the UNICT-VEDI cultural-site dataset, plus a WSOL distillation pipeline that auto-labels a YOLO dataset from the DINO classifier. Code comments and docs are in Italian.

## Environment / commands

- Python 3.12, deps live only in `venv/` (torch 2.13+cu126, transformers 5.x, ultralytics, torchmetrics). CUDA is available; these scripts realistically require a GPU.
- `pyproject.toml` and `uv.lock` are effectively empty (the project itself only). Do **not** rely on `uv sync` / `pip install -e .` to set up the environment — it will not install torch/transformers/ultralytics.
- Always run scripts from the repo root with the venv interpreter, e.g. `.\venv\Scripts\python.exe train_obj_det_dinov3.py`. Root scripts use paths like `./data/...`, `./checkpoints_...`; only `script/check_corrupted_images.py` uses `../data/...` and must be run from `script/`.
- There are no CLI args, linter, formatter, typechecker, or test suite. Hyperparameters are hardcoded inside each script's `train()`/`evaluate()`.

## Pipeline order (dependencies matter)

1. `train_obj_det_dinov3.py` — DETR-style detection on DINOv3 → `checkpoints_detection/best_model.pth` + `class_map.json`.
2. `train_classification_dinov3.py` — DINO + linear classifier → `checkpoints_classification/best_model.pth` + `class_map.json`.
3. `autogenerate_yolo_dataset.py` — loads checkpoint from step 2, uses WSOL heatmaps to pseudo-label `data/dataset_yolo_distilled/` (teacher→student distillation).
4. `train_yolo_autogenerated.py` / `train_yolo_gt.py` — train YOLOv8n/11n/26n on distilled vs GT data.
5. `test_yolo_autogenerated.py` — evaluates those YOLO runs against the test GT.
- WSOL detection benchmarks: `evaluate_wsol_detection.py` (1 method) and `evaluate_wsol_detection_v2.py` (4 methods: linear_cam, dino_attn, eigen_cam, grad_cam). Both need the step-2 checkpoint.

## Architecture notes

- `src/model.py`: `DINOObjectDetector` is the real detection model (frozen DINOv3 ViT-S/16 backbone, multi-scale hidden states `[3,6,9,12]` with per-scale LayerNorms, 6-layer Transformer decoder, class + bbox heads). The broken `DINOClassifier` copy that used to live here (undefined `self.dinov3`) has been removed; use the working copies in the training scripts.
- `src/loss.py`: `HungarianMatcher` (`scipy.linear_sum_assignment`) + `SetCriterion` (CE with `eos_coef=0.1` background weighting, L1 + GIoU).
- DINOv3 backbone internals differ from DINOv2: blocks are `backbone.model.layer` (not `encoder.layer`), final norm is `backbone.norm` (not `layernorm`). Input is 384×384 → 24×24 patch tokens.
- `DINOClassifier` is copy-pasted (with small differences: eager attention, returning attentions) across `train_classification_dinov3.py`, `test_classification_dinov3.py`, `autogenerate_yolo_dataset.py`, `evaluate_wsol_detection*.py`, and `script/test_wsol_heatmap.py`. If you change the classifier, keep these in sync.

## Gotchas

- Class-index maps MUST follow the dataset's natural ordering (`src/dataset.py::natural_sort_key`, e.g. `3.2` before `3.10`), which is the ordering actually used by the YOLO `.txt` label ids. The inline `create_class_map` in both training scripts was previously plain `sorted()` (wrong for 32/57 classes) and is now fixed. `checkpoints_classification/best_model.pth` had a plain-sorted `class_map` embedded; it has been patched to the natural 57-entry map (backup: `best_model.pth.bak`). Keep the embedded map and `class_map.json` identical.
- `VEDIDataset` reads YOLO `.txt` class ids directly; when a frame has no label file it falls back to a full-frame box with `default_class_id` from the class map (matching the dataset README rule).
- Train/val split is `idx % int(1/val_ratio)` per class — adjacent video frames leak across splits (documented as a TODO in `diario_20_7_2026.md`). `train_yolo_*.py` deliberately replicate this exact split so DINO/YOLO validation align; don't "fix" the split in only one place.
- Ultralytics prepends `runs/detect/` to its `project` path, so `./runs_yolo_distilled` actually lands in `runs/detect/runs_yolo_distilled` (that is what `test_yolo_autogenerated.py` expects).
- `autogenerate_yolo_dataset.py`, `train_yolo_autogenerated.py`, `train_yolo_gt.py`, and `test_yolo_autogenerated.py` contain hardcoded absolute Windows paths (`C:\Users\Workstation\...`) — update them when the checkout moves.
- Data layout: `data/UNICT-VEDI_Dataset_bbox/Training/<POI-name>/{images,labels}` with 57 POI folders (folder name = class). `Test/` instead has `Test1..Test7` session folders (each mixing several POIs), so `test_classification_dinov3.py` (which passes the Training class map while scanning `Test/` as if folders were POIs) crashes with `KeyError 'Test1'` and never actually evaluates the official test set. The YOLO test scripts work because they `rglob` all images and let Ultralytics pair them with the sibling `labels/`.
- `diario_20_7_2026.md` is the design/rationale log (loss, matching, LR schedule, multi-scale choices). Treat it as background; where it disagrees with code, the code wins (e.g. it describes `unfreeze_last_n=2`, but `train_obj_det_dinov3.py` currently passes `unfreeze_last_n=0`).
