# AGENTS.md

Research project: DINOv3-based Point-of-Interest detection/classification on the UNICT-VEDI cultural-site dataset, plus a WSOL distillation pipeline that auto-labels a YOLO dataset from the DINO classifier. Code comments and docs are in Italian.

## Environment / commands

- Python 3.12, deps live in `venv/` (torch 2.13+cu126, transformers 5.x, ultralytics, torchmetrics). CUDA is available; these scripts realistically require a GPU.
- `pyproject.toml` and `uv.lock` are effectively empty (the project itself only). Do **not** rely on `uv sync` / `pip install -e .` to set up the environment — it will not install torch/transformers/ultralytics.
- Always run scripts from the repo root with the venv interpreter, e.g. `.\venv\Scripts\python.exe train_classification_dinov3.py`. All scripts use relative paths and resolve their base directories dynamically so they can be run from any folder.
- There are no CLI args for main training scripts; hyperparameters are constants configured at the top of each script.

## Pipeline order (active workflow)

1. `train_classification_dinov3.py` — DINOv3 ViT-S/16 + linear probe (57 classi POI) → `checkpoints_classification/best_model.pth` + `class_map.json`.
2. `test_classification_dinov3.py` — Valutazione del classificatore (Acc Top-1/Top-5, metriche disaggregate per classe e tier, confusion matrix).
3. `evaluate_wsol_detection_v2.py` — Benchmark WSOL dei 4 metodi di visual attribution (Linear-CAM, DINO Attention, Eigen-CAM, Grad-CAM). Richiede il checkpoint dello step 1.
4. `autogenerate_yolo_dataset.py` — Estrae le pseudo-box tramite Linear-CAM e genera il dataset distillato `data/dataset_yolo_distilled/` (teacher DINOv3 → student YOLO).
5. `yolo/train_yolo_autogenerated.py` / `yolo/train_yolo_gt.py` — Addestra lo studente YOLOv8n (o 11n/26n) su dati distillati vs Ground Truth.
6. `yolo/test_yolo_autogenerated.py` — Valuta i rilevatori YOLO sul set di test e calcola mAP@50 e per-tier retention.
7. `yolo/train_for_sample_efficiency.py` & `yolo/test_for_sample_efficiency.py` — Studio di sample efficiency a quote progressive (1%..100%, 3 seed stocastici).
8. `visualize_dino_bbox.py` — Campiona e salva confronti visuali tra le box DINO e il Ground Truth in `visual_sample_dino_vs_gt/`.

## Architecture notes

- `src/model.py`: Contiene il modello canonico `DINOClassifier` (backbone DINOv3 ViT-S/16 congelabile, testa lineare, estrazione flessibile di hidden_states e attention maps per CAM), oltre a `DINOObjectDetector`.
- `src/dataset.py`: `VEDIDataset`, ordinamento naturale `natural_sort_key` e `create_class_map`.
- `src/loss.py`: `HungarianMatcher` e `SetCriterion` (utilizzati originariamente per esperimenti DETR).
- DINOv3 backbone internals: blocks su `backbone.model.layer` (non `encoder.layer`), final norm su `backbone.norm`. Input a 384×384 → 24×24 patch tokens.
- `archive/`: Contiene i rami di sviluppo e prototipi precedenti archiviati:
  - `train_classification_dinov3_v2.py` & `checkpoints_classification_v2/` (esperimento con classe background 'Negatives' = 57, superato dall'approccio v1 canonico).
  - `evaluate_wsol_detection.py` & `wsol_benchmark_results.txt` (vecchio benchmark a singolo metodo, rimpiazzato da v2 a 4 metodi).
  - `train_obj_det_dinov3.py` (esperimento preliminare DETR-style).

## Gotchas

- Class-index maps DEVONO seguire l'ordinamento naturale (`src/dataset.py::natural_sort_key`, es. `3.2` prima di `3.10`), che corrisponde all'ordinamento reale degli id `.txt` di YOLO.
- `checkpoints_classification/best_model.pth` ha la mappatura a 57 classi allineata a `checkpoints_classification/class_map.json`. Mantieni sempre i due allineati.
- Train/val split deterministico: `idx % int(1/val_ratio)` per classe. `yolo/train_yolo_autogenerated.py` replica fedelmente questo split per garantire coerenza sperimentale tra teacher e student.
- Ultralytics salva i run aggiungendo `runs/detect/` al prefisso `project`, perciò `./runs_yolo_distilled` si trova fisicamente in `runs/detect/runs_yolo_distilled`.
